About me

I like solving problems most people wouldn't think to build software for. They're small, specific, easy to overlook, but genuinely annoying once you notice them. If something about my day bugs me enough, I'll just build the fix myself. I'm also a total AI fanatic, so there's usually one worked into the solution somewhere.

I spent close to a decade in hospitality, including Michelin-starred restaurants, and genuinely loved it, but it never quite felt like where I was meant to end up. I've always liked being mentally stretched, so on a bit of a whim I started studying software development at university, mostly just to see if it clicked. It did, instantly. It's the first thing I've wanted to see all the way through, and now it's all I want to do.

That hospitality instinct hasn't gone anywhere, though. Reading a room, staying composed under real pressure, treating every small detail like it matters, because it does. I bring the same care to code. I like understanding a problem end to end, from the database up to the pixel on screen, and I love both halves of that equally: the logic and the craft.

Projects

Karma

A team project and my first real client work, built by five of us as consultants at Assimilatus. Karma is an Android app that connects volunteers with organizations that need a hand, from shifts at a food bank to handing out parcels. Within the team I owned the applications and shifts side end to end: volunteers find work that fits their availability and apply, and coordinators review, accept, and staff every shift.

Built using: Kotlin, Jetpack Compose, Material 3, Retrofit, Node.js, Express, TypeScript, Prisma, PostgreSQL, GitHub Actions

  • Volunteer Shifts tab: browse, apply for, and withdraw from shifts
  • Coordinator inbox to accept or reject applications, with capacity checks per shift
  • "Find work that fits": shifts filtered by each volunteer's own availability
  • Karma points and rewards that volunteers earn and redeem
  • Multi-module Android app with one module per feature, backed by a REST API

Client project, code is private.

Pantry Panic

I can barely cook, so I turned to HelloFresh to learn. It got expensive fast, so I decided to build something of my own instead: a goofy, cheerful app that helps me push through the panic of what to eat and puts a smile on my face while doing it. Pantry Panic can generate an AI recipe for just tonight's dinner or plan out my entire week, then writes the shopping list and walks me through every recipe.

Built using: Next.js, TypeScript, Expo / React Native, Supabase, PostgreSQL, Claude API, GitHub Actions

  • Recipe library with AI suggestions by mood or ingredients on hand, full step-by-step instructions included
  • Favorites and tags to organize saved recipes
  • Weekly planner with breakfast, lunch, and dinner slots
  • Auto-generated shopping list that combines duplicate ingredients across the week
  • Private accounts with row-level security protecting each user's recipes, plan, and list

Recipe for Disaster

A single-player Android restaurant-management game where you keep a restaurant alive for as many in-game days as you can. Staff, customers, inventory, equipment, and random events all feed into a simulation built to create its own chaos instead of scripted moments. Still in development.

Built using: Kotlin, Jetpack Compose, Material 3, Room, JUnit

  • Simulation engine in pure Kotlin, separate from Android and unit-tested on the plain JVM
  • Library of 25 events plus player decisions that shape each run
  • Room persistence for saved games
  • Multi-module architecture: domain, data, and app
  • Balance simulations that report survival stats per play style
